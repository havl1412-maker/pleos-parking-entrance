# 다음 단계 계획

지금 앱은 사람이 미리 조사한 입구 데이터(좌표, 몇 번째 경사로, 사진)를 쓴다. 아래는 그다음 단계로 생각하는 것들이다. 아직 구현하지 않았다.

## 1. 빌트인 캠으로 입구 사진 자동 수집

**하려는 것**: 차가 주차장 입구로 들어갈 때 빌트인 캠(전방 카메라)에 찍힌 장면을 입구 사진으로 쓴다.

- 입구 300m 전 ~ 진입 순간 사이의 전방 영상에서 "멀리서 본 장면"과 "정면 장면"을 한 장씩 고른다.
- 주차 후 "안내한 입구가 맞았나요?"에 "맞았어요"라고 답한 주행의 사진만 후보로 올린다. 기어 P와 위치로 실제 그 건물에 들어갔는지도 함께 확인한다.
- 낮·밤, 공사·간판 교체 같은 변화를 사람이 다시 가지 않아도 반영할 수 있다. 사진이 없는 입구도 처음 한 대가 들어가면 채워진다.
- 얼굴과 번호판은 기기 안에서 가린 뒤에만 올리고, 사진 제공에 동의한 사용자만 대상으로 한다.

**지금 못 하는 이유**: 공개된 Pleos SDK(Vehicle, NaviHelper, FusedLocation, TextToSpeech 등)와 권한 목록에 카메라·영상 API가 없다 (2026-11-08 확인). 승인되지 않은 권한을 선언하면 앱 심사에서 탈락하므로 지금은 넣지 않는다. 영상 API가 열리거나 제휴로 접근할 수 있게 되면 진행한다.

**지금 구조에서 이미 준비된 것**

| 필요한 것 | 현재 상태 |
|---|---|
| 입구마다 사진 칸(멀리서/정면, 낮/밤) | `entrances.json` 의 `photoFar`, `photoNear`, `photoFarNight`, `photoNearNight` |
| 사진을 찍을 시점 | 안내 상태(300m 전 → 입구 앞 → 주차 완료)가 이미 있다 |
| 맞는 입구였는지 확인 | 주차 후 피드백 버튼, 기어 P + 위치로 "옆 건물일 수 있어요" 판단 |

## 2. 그 밖의 계획

- **사용자 피드백으로 데이터 고치기**: 지금은 "아니었어요"와 그 이유(다른 경사로 / 닫혀 있었음 / 사진·설명과 다름)를 차 안에 저장하고, 다음에 같은 입구를 안내할 때 한 번 더 확인하라고 알려 준다(`data/FeedbackLog.kt`). 다음 단계는 동의한 사용자의 기록을 모아, 틀렸다는 답이 쌓인 입구를 다시 조사 대상으로 올리는 것이다. 이유가 있어서 데이터의 어느 칸(순서·운영 시간·사진)을 고칠지 알 수 있다.
- **비 오는 날 더 일찍 안내**: 와이퍼가 켜져 있으면 미리 보기를 10초 더 일찍 띄운다. 엔진 쪽은 만들어 두었고(`GuidanceEngine.extraLeadSec`), 와이퍼 신호와 잇는 것은 API 사용법이 확인되면 한다(docs/sdk-check.md 10절).
- **출구 안내**: 나갈 때 출구 방향과 정산 방법. 데이터에 입구/출구 구분(`kind`)은 이미 있다.
- **차량 높이 자동 입력**: 지금은 운전자가 직접 넣는다. 차량 제원을 읽을 수 있는 API가 있으면 자동으로 채운다.
- **데이터 형식 공개**: 오픈스트리트맵의 주차장 입구 태그(`amenity=parking_entrance`, `maxheight`)와 맞춰 다른 서비스와 주고받을 수 있게 한다. 참고: https://wiki.openstreetmap.org/wiki/Tag:amenity%3Dparking_entrance
