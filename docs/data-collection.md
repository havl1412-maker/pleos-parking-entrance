# 시연용 입구 데이터 수집 가이드 (팀원용)

시연할 장소 3~5곳의 주차장 입구를 직접 조사해서 앱에 넣는다. 한 곳당 30분 정도 걸린다.

## 1. 어떤 장소를 고르나

- 상가 건물이 붙어 있어서 **경사로 입구가 여러 개 연달아 보이는 곳**
- 내비가 "목적지 부근"이라고 할 때 진짜 입구가 어느 것인지 헷갈리는 곳
- 들어가는 입구와 나가는 출구가 따로 있는 곳이면 더 좋다
- 팀원 중 실제로 헤맨 적 있는 곳이 가장 좋다(기획서의 실제 사례가 됨)

후보를 정하면 단톡에 장소 이름과 지도 링크를 먼저 공유하고 겹치지 않게 나눈다.

## 2. 안전과 개인정보

- **운전 중에 촬영하지 않는다.** 동승자가 찍거나, 걸어가서 인도에서 찍는다.
- 사람 얼굴과 자동차 번호판이 크게 나오지 않게 찍는다. 나오면 나중에 모자이크한다.
- 건물 안(사유지)에 들어가지 말고 공공 도로·인도에서 찍는다.

## 4. 사진 찍는 법

핵심: **운전자가 차 안에서 실제로 보는 각도**로 찍는다. 운전자는 경사로를 정면으로 보지 못한다. 차선을 따라 달리면서 오른쪽 앞(좌회전 입구면 왼쪽 앞)을 비스듬히 본다. 정면은 이미 꺾어 들어가는 순간에야 보여서 안내에 쓸모가 없다.

위에서 본 그림 (오른쪽 입구, 차는 아래에서 위로 달림):

```
            │ 인도 │  건물 벽
            │      ├──────────┐
            │      │ 두 번째  │ ← 목적지 경사로 (near: 꺾기 직전 이 입을 비스듬히)
            │      ├──────────┘
            │      │ 편의점
            │      ├──────────┐
            │      │ 첫 번째  │ ← 옆 건물 경사로 (헷갈리는 입구)
            │      ├──────────┘
   ↑ 진행   │      │
  [near] ●  │      │   5~10m 앞, 차선 위치에서 오른쪽 앞 약 45°
            │      │
  [far]  ●  │      │   30~50m 앞, 차선 위치에서 진행 방향 오른쪽 앞 약 20~30°
            │      │   (첫 번째·두 번째 경사로가 앞에서부터 순서대로 한 화면에)
```

- **far (멀리서, 300m 전 화면에 나옴)**: 입구 30~50m 앞, 차선 위치에서 운전자 눈높이(약 1.2m)로 진행 방향 오른쪽 앞을 비스듬히 찍는다. 옆 건물 경사로와 목적지 경사로가 **앞에서부터 순서대로** 한 화면에 들어와야 한다. 앱의 "첫 번째 ✕ 옆 건물 → 두 번째 ✓ 여기" 약도와 같은 순서다.
- **near (가까이서, 입구 앞 화면에 나옴)**: 꺾기 직전, 입구 5~10m 앞에서 오른쪽 앞 약 45°로 찍는다. 입구 간판, 차단기, 높이 제한 표지판처럼 "여기가 맞다"를 확인할 수 있는 것이 보이게 한다.
- **왼쪽 입구(좌회전)**: 같은 방법으로 왼쪽 앞을 비스듬히 찍는다.
- **정면 사진은 찍지 않아도 된다.** 길 건너에서 본 건물 정면이나 경사로 정면은 운전자가 보는 장면이 아니다.
- **운전 중에는 찍지 않는다.** 인도의 차도 쪽 가장자리에 서서 차선과 비슷한 위치·각도로 찍거나, 정차 중 동승자가 찍는다. 차도 안으로 들어가지 않는다.
- 가로로 찍는다. 앱 카드가 가로로 넓다.
- 헷갈리는 옆 입구(앞쪽)와 다음 입구(뒤쪽)도 같은 각도(near)로 한 장씩 찍어 둔다(기획서·검수용).
- 파일 이름: `장소번호-입구번호-far.jpg`, `장소번호-입구번호-near.jpg` (예: `03-1-far.jpg`)

## 5. 실측 (기획서 근거용, 가능하면)

국내에는 "입구 찾는 데 걸린 시간"만 따로 잰 통계가 없다. 우리가 직접 재면 기획서의 강한 근거가 된다.

- 처음 가는 사람이 운전(또는 동승)해서 "목적지 부근" 안내가 나온 순간부터 입구에 들어갈 때까지 걸린 시간
- 입구를 지나쳐서 다시 돌아온 적이 있는지, 몇 번인지
- 날짜, 시간대, 날씨

## 다 넣은 뒤 확인

앱을 debug 로 설치해서 열면, `entrances.json` 에서 틀려서 뺀 곳이 대기 화면에 빨간 카드("입구 데이터 확인 필요")로 나온다. 쉼표·따옴표가 틀린 경우, 모르는 값(`roadSide: "RIHGT"`), 위도·경도를 바꿔 적은 경우, 운영 시간표를 잘못 적은 경우, 없는 사진 파일 이름, 겹치는 id 를 알려 준다. 틀린 입구만 빠지고 나머지는 그대로 안내한다. 단위 테스트(`gradlew testDebugUnitTest`)도 저장소의 `entrances.json` 에 문제가 하나라도 있으면 실패한다.

같은 칸을 한 입구에 두 번 적지 않는다. 차(안드로이드)에서는 뒤에 적은 값만 쓰이고 아무 표시도 안 나서 알아채기 어렵다.

## 11/10 추가된 데이터 칸

- `photoFarNight`, `photoNearNight`: 밤에 찍은 사진(선택). 밤 모드에서 우선 보여 준다. 가능하면 낮과 같은 자리에서 한 장씩 더 찍는다.
- 입구가 여러 개인 건물은 입구마다 `approachBearingDeg`(주로 들어오는 방향, 북=0·동=90)를 꼭 적는다. 앱이 달리는 방향과 가장 잘 맞는 입구를 고른다.
- `confusers[].after`: `true` 면 목적지를 지나치면 바로 나오는 뒤쪽 경사로다(11/11 추가). 약도에 "세 번째 ✕ 다음 건물" 칸이 생기고, 입구 앞 경고·음성과 지나쳤을 때 "바로 다음 경사로는 다른 건물" 안내에 쓰인다. 없으면 앞쪽(기본).
- `schedule`: 요일·시간별 운영 상태(11/11 추가). `hoursText` 는 화면에 그대로 보여 주는 글이고, `schedule` 은 앱이 지금 시각과 견줘서 "지금은 문을 닫았어요 / 지금은 무료 개방 / 22:00에 문을 닫아요"를 판단하는 표다. 없으면 판단하지 않는다.
  - `rules`: 위에서부터 처음 맞는 규칙을 쓴다. `days` 는 `"월-금"`, `"토,일"`, `"매일"`, `"평일"`, `"주말"`, `"공휴일"`, `from`·`to` 는 `"09:00"`~`"24:00"`(`from` 이 더 크면 자정을 넘는 구간), `status` 는 `PAID`(유료 운영) / `FREE`(무료 개방) / `CLOSED`(폐쇄).
  - `otherwise`: 맞는 규칙이 없는 시간의 상태. 공영 주차장은 보통 `FREE`, 밤에 막는 건물은 `CLOSED`.
  - `"공휴일"` 규칙이 있으면 공휴일에는 요일 규칙 대신 그 규칙만 본다. 공휴일 날짜는 파일 맨 위 `holidays`(`"MM-DD"` 는 해마다, `"YYYY-MM-DD"` 는 그해만)에 적는다. 설·추석·대체 공휴일은 직접 넣어야 한다.
  - 예 (공영 주차장):

    ```json
    "schedule": {
      "rules": [
        {"days": "공휴일", "from": "00:00", "to": "24:00", "status": "FREE"},
        {"days": "월-금", "from": "09:00", "to": "19:00", "status": "PAID"},
        {"days": "토", "from": "09:00", "to": "15:00", "status": "PAID"}
      ],
      "otherwise": "FREE"
    }
    ```
- `naviLat`, `naviLng` (시설에 하나, 선택, 11/11 추가): 내비에서 이 건물을 목적지로 고르면 안내가 끝나는 지점. 내비 목적지가 여기(또는 입구)에서 100m 안이면 "이 건물에 가는 것"으로 보고, 입구에서 25m 넘게 떨어져 있으면 내비 목적지를 입구로 바꾸자고 한다. 없으면 입구 좌표로만 판단한다.
- `heightLimitM`: 입구 미리 보기 화면에 나오고, 운전자가 넣어 둔 차 높이보다 낮으면 경고한다. 표지판 숫자 그대로 적는다.
